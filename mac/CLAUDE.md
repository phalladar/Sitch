# Sitch for macOS (`mac/`)

Native Swift port of the Windows app in `../windows/Sitch`, which stays the reference
implementation: translate its behavior and mirror its module names (`App/`, `Capture/`, `Core/`,
`Editor/`, `Export/`, `Shell/`). Roadmap and the C# → Swift mapping table: `../docs/MACOS_PORT.md`.
Status: **feature-complete port** (capture, editor with all 14 tools, export/share, shell), released
since v0.2.0. `SitchCore` (library) holds the model + renderer and is covered by `swift test`.

## Stack
- Swift 6 language mode, AppKit (code-built windows, no nibs/storyboards), SwiftPM only — open in
  Xcode with `open Package.swift`. No third-party dependencies. macOS 15+, universal binary.
- Bundle id `io.github.phalladar.Sitch`. Info.plist is generated by `scripts/build-app.sh`
  (`LSUIElement`: menu-bar app; it flips to `.regular` only while an editor window is open).

## Build / run / test (from `mac/`)
- `swift build` / `swift run` — bare binary, no bundle (no icon, no Info.plist, no single-instance).
- `swift test` — SitchCore unit tests (render origin, crop, undo, rotate/flip, effects, settings…).
- CLI flags as on Windows: `--demo`, `--demo-crop`, `--demo-light`, `--settings`, `--capture`, a
  file path, and headless `--shot-region=<png>`; plus `--render-demo=<png>` (flattened demo
  document — compare with `docs/assets/editor-dark.png` for render parity). A second launch of
  the BUNDLED app forwards its args to the running one (distributed notification), so test a
  fresh launch only after quitting it.
- `./scripts/build-app.sh` → `.build/Sitch.app`. `UNIVERSAL=1` for arm64+x86_64; `VERSION` defaults
  to the Windows csproj `<Version>` (one version line for both platforms).
- `SIGN_IDENTITY="Developer ID Application: Mind Meat Machine, LLC (G99WQY2ZW3)"` signs with the
  hardened runtime + timestamp (identity is in the login keychain). Use it for dev builds once
  capture lands: ad-hoc rebuilds lose the Screen Recording grant.
- `./scripts/make-dmg.sh [Sitch.dmg]` — the installer: drag-to-Applications disk image with
  background art (`scripts/make-dmg-background.swift`, stored in the app as
  `Resources/DMGBackground.tiff` so no `.background` folder shows), signed + notarized + stapled when
  `SIGN_IDENTITY` / `NOTARY_*` are set. Run it after `notarize.sh` so the app inside is stapled.
  The Finder layout step needs Apple Events to Finder; if refused it warns and ships unstyled.
- Open at login: offered once (`settings.offeredLoginItem`) on the first launch from an
  Applications folder — a pre-checked box in the first-run Welcome, else an alert
  (`Shell/LoginItemOffer.swift`). Copies on the disk image or translocated get an
  "install first" note instead, since a login item there would point at a vanishing path.
- `swift scripts/make-icon.swift Resources/AppIcon.icns` regenerates the icon (vector redraw of
  the Windows `.ico`); the `.icns` is committed.
- `./scripts/smoke-test.sh <binary> [seconds]` fails if the app exits during launch.
- UI can be driven headlessly with `osascript` + System Events (menu bar 2 = the status item);
  the global hotkey fires for `key code 21 using {command down, option down}` (not `keystroke "4"`),
  and synthetic `CGEvent` drags work on the capture overlay. Running the bundle's binary from a
  terminal inherits the terminal's Screen Recording grant; `open`-launching it uses its own.

## Layout
`Sources/SitchCore` (model, annotations, Renderer, EffectRenderer, settings, HotkeyChord, demo) ·
`Sources/Sitch/App` (AppController = Windows App.xaml.cs, menus, single instance, Theme tokens) ·
`Capture` (ScreenCaptureKit freeze, per-display overlays, window list) · `Editor` (window
controller split by concern, DocumentCanvas, chrome controls, pickers, SVG path parser for the
Windows glyph strings) · `Export` (encoders, clipboard, temp files, share) · `Shell` (toast,
countdown, Carbon hotkeys, login item, screenshot watcher, Settings, Welcome).

## Signing & release
No entitlements file: capture is gated by the Screen Recording privacy grant, not an
entitlement. Releases are cut by the repo-root `.github/workflows/release.yml` (see root
CLAUDE.md); `scripts/notarize.sh` uses an App Store Connect API key (`NOTARY_KEY_PATH`,
`NOTARY_KEY_ID`, `NOTARY_ISSUER_ID`), staples, and zips with `ditto`.
CI links a newer SDK (macos-26 runner) than local SwiftPM builds record, which can change AppKit
behavior — trust a CI-built smoke test over a local one.
